# 工厂交流与任务卡模板

这份表用于第一次现场交流。当前不需要主管先给出确定的机器人选型；先从业务任务和接口约束缩小研究范围。下面均为待填写项，不是已确认的集团需求。

## 1. 开场说明

“实验室正在评估具身智能能在哪些工位产生价值。我们希望先了解重复操作、变化情况和失败代价，选一个范围可控的任务做基线。今天不承诺替代现有系统，也不要求立即采购机器人。”

## 2. 两类候选任务用同一张表比较

| 字段 | 机械臂候选 | 人形候选 |
|---|---|---|

| 当前人员做的完整操作 | 待填写 | 待填写 |
| 开始条件与结束条件 | 待填写 | 待填写 |
| 工件种类、尺寸、重量、柔性 | 待填写 | 待填写 |
| 常见位置、光照、遮挡变化 | 待填写 | 待填写 |
| 合格定义、公差、允许损伤 | 待填写 | 待填写 |
| 当前节拍、人工干预、返工 | 待填写 | 待填写 |

第一轮优先选可以重复重置、结果可判断、现场可持续接触的候选。人形场景要说明为什么需要人形或移动能力；机械臂场景也要与现有视觉、规划和自动化基线比较。研究深度相同不意味着必须同时购买两套设备。

## 3. 从机器人或集成商取得的接口资料

| 必须弄清的内容 | 为什么影响数据 |
|---|---|
| 关节名及顺序、单位、正方向、限位 | 相同维度不代表相同动作 |
| 接收位置、速度、力矩、末端增量或技能 | 决定监督标签与控制接口是否一致 |
| 动作在哪个坐标系表达，工具和末端定义 | 决定能否转换以及是否需要 IK |
| 指令时间、执行时间、反馈时间与时钟域 | 决定观测—动作是否配对正确 |
| 控制频率、延迟、插值和丢包行为 | 决定动作块与重采样方案 |
| 相机序列、内外参、深度、时间戳 | 决定视觉输入与标定记录 |
| 夹爪／灵巧手物理量与映射 | 不能把闭合度误当关节角 |
| 人形根部位姿、IMU、足接触、全身控制器 | 上身示范不能自动监督步态和平衡 |
| 人工接管、急停、执行裁剪的日志接口 | 需要区分请求动作与实际执行命令 |
| SDK 与服务器 OS、GPU、仿真支持版本 | 数据管线兼容不代表整套机器人软件兼容 |

先用厂商提供的最小示例采一条完整记录，检查时间和单位；不要仅根据销售演示视频判断数据可接入程度。

## 4. 第一轮试验记录模板

每次试验保留 `trial_id、task_version、robot_config、model_checkpoint、data_release、seed/初始条件、开始结束时间、成功判据、结果、干预次数、节拍、失败类型、视频与日志引用`。

报告给出成功数 / 总试验数，不只展示成功视频。训练与评测按会话、对象或场景分开；具体分组对应想验证的泛化问题。固定模型、算力和评测任务后比较数据配方，才有依据说明新增数据的收益。

## 5. 两周复盘的输出

一页记录：已排除哪些候选及原因、剩余候选的价值与技术难点、现有资源缺口、下一轮实验、需要主管协调的事项。暂时未找到合适工位也可以形成有效结论；用证据解释，避免以下载总 TB 数代替研究进展。
