# 面向多本体 VLA 的数据 Pipeline 设计

## 1. 目标与工程边界

目标是让新数据通过可复用的接入与验证流程，形成有来源、时序正确、动作语义明确的数据资产，再生成特定模型可训练的输入。第一次接入新格式或新机器人通常需要编写适配器；相同契约的后续批次才能自动处理。

**不能承诺任意原始数据放进一个文件夹就自动成为所有模型的训练集。** 缺少动作命令、坐标系、标定或合法来源的信息不能靠改字段名补齐；流水线必须明确输出“不适合这个训练视图”的原因。

本文件是下一阶段实施设计，不是已完成的服务。现阶段优先实现离线 batch 导入和确定性导出，无须先部署大型流式集群。

## 2. 建议的数据分层

```text
公开数据 / 仿真生成 / 遥操作 / 自主执行 / 商业交付
                         │
             来源登记 + 版本 + 权利记录
                         │
               原始层：不可变原件与哈希
                         │
            接入解析 → 时间对齐 → 物理语义校验
                         │
              规范层：完整轨迹、模态、标注
                         │
           质量分级 → 去重 → 分组切分 → 数据配方
                         │
              训练视图：按模型定义输入与标签
                ┌────────┼─────────┐
              openpi   GR00T   OpenVLA / 其他
                │         │          │
              训练 → 评测 → 部署记录 → 新数据
```

原始层保留完整信息；规范层统一语义而不强行抹平本体差别；训练视图负责模型偏好。只在规范层统一成 7 维动作，会提前丢掉双臂、手指、底盘和全身信息；只保留某个模型归一化后的动作，也会让以后换模型困难。

LeRobot v3 适合规模化训练存储，但当前许多配方仍要求 v2 或带扩展的 v2。建议第一版同时接受 v2/v3，模型导出按固定配方生成；规范层可采用 Parquet+视频+sidecar 元数据，但这只是实现选择，不把“LeRobot 格式”当作完整物理语义标准。[^34][^32]

## 3. 数据契约：先定义含义，再定义目录

### 3.1 六类核心记录

| 记录 | 最少应包含的信息 |
|---|---|
| SourceManifest | 来源 ID、原 URL、revision、文件清单、哈希、许可及条款记录、访问日期、原始规模口径、父数据集 |
| EmbodimentSpec | 厂商／型号／序列或版本、关节名称顺序、运动学资产引用、工具与手型、相机、传感器、控制器版本和动作接口 |
| Episode | 全局 ID、source ID、原始 episode ID、父会话／父示范、任务、对象、场景、采集策略、起止时间和结束原因 |
| Streams | 每路观测／命令的原始时间戳、时钟域、采样率、单位、坐标系、媒体位置、是否缺失／插值 |
| Annotations | 语言与子任务时间段、成功／失败、质量、接管、奖励、标注方法及置信度、版本 |
| TrainingViewManifest | episode 列表与 split、过滤规则、采样权重、规范版本、模型适配器版本、归一化统计、mask 和导出参数 |

没有实测的质量字段用 `unknown` 或 `null`。不要把 `success=null` 改成 false；不要将 human_video 填上全零动作后混入行为克隆。

### 3.2 一个本体配置的教学示意

下例是自拟配置草案，不是某厂家真实标定，也不是 LeRobot 官方 schema。它说明动作为什么不能只有一个 shape。

```json
{
  "embodiment_id": "lab_arm_A_v1",
  "action_spaces": {
    "arm": {
      "type": "joint_position_target",
      "joint_names": ["j1", "j2", "j3", "j4", "j5", "j6", "j7"],
      "unit": "rad",
      "command_frame": "joint",
      "target_timing": "issued_after_observation_for_next_control_interval"
    },
    "gripper": {
      "type": "opening_width_target",
      "unit": "m",
      "zero_means": "closed"
    }
  },
  "timing": {"policy_hz": 20, "clock_domain": "robot_monotonic"},
  "kinematics": {"asset_id": "lab_arm_A_urdf_revision_1"},
  "controller": {"id": "joint_position_controller_v1"},
  "calibration_id": "workcell_A_calibration_revision_1"
}
```

人形还要加入 root 的定义、四元数顺序、足部接触、IMU 坐标、全身参考或技能接口。根部位姿是浮动基座描述，不是可独立直接驱动的电机。手部数据必须明确是物理关节角、归一化闭合度还是厂商协同控制量。

### 3.3 一个 episode 的最低契约

每条 episode 至少回答：来自哪次采集、哪台配置的机器人、要做什么、各路时间如何关联、哪些动作实际发出、如何结束。失败轨迹应保留失败类型和时间段；自主执行保留 policy/checkpoint；人工干预保留开始和结束以及操作者动作。

建议命令层同时保留 `proposed_action`、`executed_command`、`observed_state`。前者是模型／操作者请求，第二项是经过裁剪、IK 或控制器限制后的实际发送命令，第三项是测量结果。特定训练视图应声明选择哪一个为 target。

## 4. 接入适配器

### 4.1 先实现哪些 reader

| 顺序 | Reader | 起步样本 | 必须验证 |
|---|---|---|---|
| 1 | LeRobot v2.1 | NVIDIA G1、宇树 Dex1 | 视频与 step 关联、meta 解析、关节顺序、task index |
| 2 | LeRobot v3 | 宇树 WBT、ABC smoke | 跨文件 episode 边界、视频 offset、分片索引 |
| 3 | RLDS / TFDS | DROID 100 episodes | episode 嵌套、终止末步、action_dict、版本 |
| 4 | 仿真 HDF5／工具专用格式 | RoboTwin 或自建 Isaac Lab 环境 | 环境版本、动作定义、初始状态、成功判定 |
| 5 | MCAP / ROS 消息 | 自采日志或 ABC 原始数据 | topic schema、多时钟、标定、媒体解码与命令关联 |
| 6 | 商业交付／人体视频 | 按验收契约 | 字段完整性；缺少动作时进入辅助学习分支 |

解析器只负责忠实解码；坐标转换、质量筛选和模型导出应是独立步骤。一个 reader 修改后，可以重新跑同一组 golden episodes 判断是否改变了数据含义。

### 4.2 不适配的输入如何处理

必须有明确状态，例如 `registered → downloaded → parsed → validated → split_assigned → released`，另有 `quarantined` 和 `rejected_for_view`。解析失败不是整批静默跳过；记录 episode ID、阶段、原因和受影响字段，允许修复后定点重跑。

人类视频可以是合法且有价值的数据，但不符合 action-BC 视图；同样，成功的 RGB 轨迹可能不符合力控视图。拒绝的是某个用途，不一定是整个数据资产。

## 5. 时间对齐与动作语义

### 5.1 时间同步必须保留因果关系

优先使用设备硬件时间或已标定的共同时间基准。原始时间不丢弃：分别记录传感器采样、消息接收、动作发出和可用时刻。若存在多个设备时钟，校准 offset/drift，记录校准有效期。

对齐策略要按字段定义：图像可按帧时间匹配；连续状态可在允许区间插值；离散夹爪开闭、模式切换、接触事件不随意线性插值。RGB、深度和触觉可以保留各自原始频率，仅在模型训练视图取样。

离线处理也应模拟推理时可得到的信息。选择“最近帧”时可能选中未来才产生的图像，形成因果泄漏；应根据模型的 observation 可用时刻、允许延迟和对齐方案选择过去帧，或明确证明所选帧在决策前可用。不能用训练时才有的未来平滑状态当作在线观测。

### 5.2 重采样不能一律取每隔 N 帧

| 原动作含义 | 从 30 Hz 变成 15 Hz 时的原则 |
|---|---|
| 绝对关节／末端目标 | 在新的控制时刻取对应目标，必要时按运动学约束插值 |
| 逐步位移／旋转增量 | 合成新时间段内的增量；旋转用正确群运算，不能逐元素相加 |
| 速度命令 | 按时间加权、重新积分核验；不要误乘与位移相同的缩放 |
| 力矩或力命令 | 取样方法与控制器／动力学相关；不能只做几何转换 |
| 夹爪事件 | 保留开合事件与持续状态，避免抽样漏掉瞬时动作 |

模型的 action chunk 长度对应真实时间，重采样后需要同步检查 prediction horizon 和 execution horizon。统计报告应列原始频率、目标频率、drop/duplicate/interpolation 比例及最大时序间隙。

### 5.3 统一坐标与旋转约定

所有位姿字段都应记录 `reference_frame`、`body/tool_frame`、长度单位及旋转表示。明确 `xyzw` 和 `wxyz`，欧拉角的内禀／外禀与旋转顺序，以及左乘／右乘。旋转插值使用合适的几何方法；不要把跨 ±π 的角度直接线性平均。

对单臂、双臂和人形使用局部任务坐标可以增强复用，但必须保留到原始坐标系的变换。双臂应共享时间和对象参考；人形要处理 root/world/foot/hand 的关系，不能把漂移的 odometry 当作永久精确 world。

### 5.4 终止与截断

RLDS 标准里 `is_last` 的末观测不应默认存在有效的后续动作；`is_terminal` 与时间截断不同。公开转换器有时存在注释或约定差异，reader 要做来源特定验证。[^35]

内部应独立保留 `terminated`、`truncated`、`success` 和 `abort_reason`。超时结束不等于环境吸收终态；视频最后一帧不等于成功。RL 导出时还要明确奖励是属于动作前、动作后还是整个 transition，避免一帧错位影响价值目标。

## 6. 质量管理：保留失败，隔离坏数据

### 6.1 质量检查分四层

| 层次 | 检查例子 | 处理方式 |
|---|---|---|
| 文件完整性 | 哈希、视频可解码、Parquet schema、引用文件存在 | 不完整数据隔离，支持断点重取 |
| 时序与物理一致性 | 时间单调、关节数量、单位、NaN、极端跳变、FK 与末端轨迹差异 | 记录异常段，按严重性隔离或标记 |
| 任务与监督质量 | 指令是否指向正确对象、success 是否可信、无效等待、接管边界 | 人工抽样复核，质量分级并路由不同视图 |
| 分布与覆盖 | 单一操作者占比、失败类型、工位多样性、重复和稀有任务 | 采样重加权或补采，不仅仅删除 |

高频并不自动等于高质量；视频重复编码、未同步的双手轨迹、命令被控制器裁剪但未记录，都可能破坏监督。

### 6.2 失败数据如何利用

| 数据段 | 推荐用途 | 不应怎样使用 |
|---|---|---|
| 专家成功操作 | 行为克隆、技能微调 | 无条件忽略中间低质量和错误动作 |
| 明确失败行为 | 价值／奖励、失败识别、评测 | 当成正向专家示范整段混入 |
| 失败后的专家纠正 | 恢复技能、干预学习 | 丢掉起始偏离状态只留下“完美”后半段 |
| 设备／记录故障 | 工程诊断 | 当作策略探索失败计算奖励 |
| 合法等待 | 阶段与控制状态学习 | 被统一 idle filter 删除 |
| 不确定质量 | 待复核或低权重辅助视图 | 自动标成成功 |

“静止”既可能是操作者走神，也可能是等待物体落稳、设备夹紧或避让。因此 idle filter 需要任务阶段与控制状态。来源相关的过滤阈值应该可追溯并可消融，不能使用一套全局速度阈值处理所有工位。

## 7. 去重、切分与数据泄漏

### 7.1 先确定来源关系，再切训练集

按完整 episode、采集 session、场景、对象实例等分组，而不是随机分帧。来自同一长任务的多个语言片段、同一个示范派生的仿真轨迹、同一个原始集的 RLDS 与 LeRobot 版本，应共享 `origin_episode_group`。

数据集已有官方 test split 时优先保留。额外的目标工位测试集必须与训练数据分开，并记录其在基础模型预训练中是否可能出现过；已公开的基准可能无法完全排除基础模型见过相关数据，要说明评估范围。

### 7.2 至少建立四种评测切分

1. 同分布留出：验证训练是否正常。
2. 新对象／新初始位姿：验证几何与外观泛化。
3. 新工位／新操作者／新班次：验证场景变化。
4. 新本体或新控制配置：在目标本体固定微调预算下评估迁移。

人形增加新地面、负载和台高；机械臂增加工具、治具、公差和接触条件。不是每一个实验都要同时做所有 OOD 测试，但报告必须说明所测泛化是哪一种。

### 7.3 去重策略

文件哈希识别相同文件；原始 episode ID 和 provenance 识别格式转换；视频／轨迹近重复检测辅助识别重新编码和切片。感知哈希只用于候选，不能把视觉相似但接触结果不同的轨迹误删。

规范层保留重复关系而不直接破坏原始层。训练 manifest 决定选哪份及权重。将同一动作反复换语言或生成背景后，应标记相关性；它不等同于增加了同样数量的独立交互。

## 8. 训练视图和模型适配

### 8.1 四类输出

| 输出视图 | 必需信息 | 可服务的训练 |
|---|---|---|
| action_bc | 当前／历史观测、语言、状态、未来动作、维度与时间 mask | 行为克隆、VLA 微调 |
| multimodal_aux | 图像／视频、文本、人体姿态或语义标签，标记 action 缺失 | 感知、语言和人类运动辅助学习 |
| transition_rl | 观测、执行动作、奖励、后继观测、terminated/truncated、策略来源 | 价值学习、离线／在线 RL |
| preference_eval | 明确比较条件、轨迹对／评分、任务结果、质量与裁判来源 | 偏好／奖励学习及评测 |

不要把纯视频导出为全零 action_bc。不要把同任务但不同初始条件的失败和成功自动当作有效偏好对。

### 8.2 数据增强与归一化

图像 resize/crop 必须与相机语义匹配；若使用深度／几何投影，同步更新相机内参。多相机和时间序列增强需要考虑一致性。翻转图像可能要求修改“左／右”指令、动作与相机坐标；这类增强不应默认启用。

归一化统计只用 training split。按兼容的物理维度和训练配方组织统计，避免把米、弧度和夹爪开合概率混在一起估计尺度。对缺失维度使用 mask，不用大量 padding 0 污染统计。统计文件随 checkpoint 保存，推理必须使用同一份。

如果复用基础模型规定的统计，应显式选择并保留其版本；如果按目标机器人重算，就同时匹配训练和推理解码。两种选择都不是“永远正确”，需要与模型配方一致。

### 8.3 不同模型的 adapter 责任

| Adapter | 主要工作 |
|---|---|
| openpi | 将 source keys 映射成 images/state/prompt/actions；设置动作绝对／增量变换、维度 padding/mask、归一化、数据混合 |
| GR00T N1.7 | 生成或读取其要求的 LeRobot v2 风格、模态映射、embodiment tag、action representation、delta indices |
| OpenVLA 原版 | RLDS 路径、图像与语言、动作标准化、离散化／tokenizer、loss mask |
| OpenVLA-OFT / 其他连续动作策略 | 支持动作块与连续 head 所需 shape、state/camera 配置及 L1 等 loss 配方 |
| 自研模型 | 接受规范层定义，再明确自己的 observation contract 和 action contract |

上述依据对应官方接入路线；实际目录、模块和 CLI 以锁定代码 revision 为准。不能因为 LeRobot 本身升级到 v3，就强制让仍要求 v2 的训练器直接读取。[^28][^32][^29][^30]

### 8.4 动作块切片和 mask

若 episode 长度 $T=100$，从 $t=95$ 取 $H=16$，最多只有 5 个有效动作。可以按模型约定填充边界并设置 mask，或丢弃不完整窗口，但不能跨到下一个 episode 的前 11 步。

有些维度在该本体不存在，需要维度 mask；有些未来时间步超出轨迹，需要时间 mask；有些动作记录本身缺失，需要有效性 mask。loss 的分母应对应参与计算的有效项，不能无意中让维度多的本体或长轨迹主导全部训练。

### 8.5 混合数据配方

建议先区分真实、合成、目标本体、其他本体、成功示范与恢复片段，再定义采样比例。以 episode 抽样和以 frame 抽样会产生不同的长任务权重，必须明确。

初期可对“只用目标数据”“目标＋相近公开”“目标＋仿真”做三组对照；不要一开始就在没有对照的情况下堆入所有来源。任何建议比例都应作为超参数，而非通用最优值。

## 9. 增量更新与可复现发布

用 `(source_id, source_revision, file_hash, parser_version)` 定位导入。规范数据与标注分开版本化，修订语言不必重编码全部视频。输出写到临时版本，完成校验后原子发布 manifest，避免训练读到半批数据。

切分规则稳定：新数据按原会话／场景等分组分配，已有 test 不因重跑而移动。统计变化会创建新的 training-view revision，不能覆盖旧模型依赖的统计文件。每次训练记录 dataset manifest hash、adapter commit、模型起点、seed、有效 batch 和过滤规则。

数据增长后可将原始层放对象存储，GPU 节点使用本地 NVMe 热缓存；数据库保存查询索引与 lineage，不能只在文件夹名字中表达全部元数据。存储系统、任务调度器和实验追踪工具可以后置选择，先用可重复的命令行阶段把数据契约验证正确。

## 10. 验收标准

| 阶段 | 发布前必须看到的证据 |
|---|---|
| 来源接入 | 小样本可读，文件／许可／版本记录完整，失败有原因 |
| 时间与动作 | 同步回放可解释，命令与反馈差异合理，坐标／单位与关节顺序通过检查 |
| 训练视图 | 无跨 episode 标签，mask 生效，归一化 round-trip 在容差内 |
| 数据集划分 | 无同源片段跨 split，test 不用于统计与过滤阈值选择 |
| 模型兼容 | 实际训练器读取至少一个 batch，loss 和梯度有限，检查点可保存恢复 |
| 能力验证 | 固定闭环测试报告，记录成功分母、质量、耗时与干预 |
| 增量更新 | 同版本重复导入结果一致，新版本可追溯并可回退 |

一个在随机数据上 shape 正确的单元测试不能替代真实 episode 回放；训练 loss 下降也不能替代机器人执行验证。第一版应对少量精选真实样本做深入核验，再扩展规模。

## 11. 实施顺序

第一阶段实现 source registry、v2/v3 reader、规范轨迹检查与一个模型导出；第二阶段加入 DROID RLDS、仿真输入、分组切分与第二个模型导出；第三阶段接入实机日志和接管记录；第四阶段才扩展到大规模混合、奖励／价值学习和自动反馈采集。

机械臂与人形共用来源、存储、时序、标注和版本系统，分别维护本体与控制适配器。单独的全身参考、力控和触觉模块可以逐步添加，不需要从一开始就把所有模态塞进一个固定向量。
