# 汇报前学习指南：用你的 LLM 基础理解 VLA 数据

这份材料供汇报人学习，不需要逐段向主管讲。建议先看第 1～5 节，再按演示脚本操作一次，最后练习第 8 节回答。

## 1. 从 LLM 换到 VLA，哪些知识能直接迁移

| 你已熟悉的 LLM 概念 | VLA 中的对应概念 | 额外要理解的部分 |
|---|---|---|
| 文本 token 序列 | 图像特征、语言 token、机器人状态 | 多路传感器需要时间关联 |
| 预测下一个 token | 预测动作 token 或未来连续动作块 | 动作具有单位、坐标和控制频率 |
| 文档／对话 | episode，一次有起止边界的操作轨迹 | 切片不能跨轨迹边界 |
| SFT 的指令与答案 | 在观测与任务条件下模仿示范动作 | 示范动作质量和执行接口影响监督 |
| tokenizer、padding、attention mask | 图像处理、状态处理、动作归一化、时间／维度 mask | 不同本体可能有不同自由度 |
| train/validation split | 按 episode、采集会话、场景等分组 | 同一示范的多种转换版本不能跨 split |
| checkpoint + tokenizer 配置 | checkpoint + 动作统计 + 本体配置 + 控制适配 | 解码错单位可能执行错误动作 |

汇报时可以说：**VLA 利用视觉、语言和机器人状态，学习在当前条件下应执行的动作。模型训练沿用深度学习方法，但数据标签具有真实的物理含义和时序要求。**

## 2. 一条训练样本到底是什么

想象机器人正把红苹果放到盘子里。某一时刻的输入是当前相机图像、任务“把红苹果放到盘子里”、当前关节状态。监督标签是接下来几个控制时刻的动作命令。

本次 G1 原始数据中，状态和动作各有 43 个值。管线保持其维度，不把它改成 7 维机械臂数据。示例训练窗口包含：

```text
image          [B, 3, 64, 64]   一路图像，演示缩小到 64×64
language       [B, L]           小模型使用 UTF-8 字节编码
state          [B, 43]          当前状态，训练集统计归一化
actions        [B, 8, 43]       从当前时刻起的 8 个动作标签
mask           [B, 8, 43]       哪些标签真实存在并参与 loss
```

这里的 64×64、字节编码和 8 步 horizon 是本原型配置，不是行业统一标准，也不是 openpi／GR00T 官方输入规格。

原数据 20 Hz 表示相邻记录通常相隔 0.05 秒。8 个动作覆盖 8 个控制周期约 0.4 秒，8 个标签时间点首尾间隔为 0.35 秒。模型一次预测动作块，不代表控制器一定一次执行整个动作块；实际重规划与执行长度需单独配置。

## 3. 模型结构与损失

一个常见结构是视觉语言骨干加动作预测模块。图像先变成特征，语言先变成 token，机器人状态通过投影进入网络，动作头根据条件预测动作。

- **离散动作路线**：动作量化成 token，用交叉熵训练，与你熟悉的 next-token prediction 接近。
- **连续回归路线**：动作头直接给出连续向量或动作块，使用 L1／L2 等损失。
- **扩散／Flow Matching 路线**：模型学习条件动作分布的去噪或向量场。训练包含噪声和时间变量，推理逐步得到动作。

不同路线各有具体实现，不能把所有 VLA 都描述成“LLM 输出电机角度”。详见主报告及其一手来源。

本次工程验证故意使用容易在本机运行的小网络：小型 CNN 读取图像、字节 embedding 汇聚语言、MLP 融合状态并输出动作块。它随机初始化，不含预训练 VLM，也没有证明语言泛化能力。其作用是把数据真实送入损失和反向传播，暴露数据工程错误。

有效动作上的示例损失为：

```text
loss = sum(mask × (prediction - target)²) / sum(mask)
```

轨迹末尾缺少未来标签时，补齐的零值不参与损失。否则模型会被训练成在结束处预测人为添加的零动作。

## 4. 为什么数据可能提升能力

数据给模型提供条件与目标动作之间的统计关系。提升什么能力，取决于数据变化了哪些条件以及提供了什么监督。

| 新增数据 | 可能改善的问题 | 仍需验证 |
|---|---|---|
| 不同物体外观与姿态的成功示范 | 对象选择、抓取姿态泛化 | 新对象、不同摆放下的真实成功率 |
| 同一工位的不同光照／遮挡 | 视觉变化下的鲁棒性 | 独立光照与遮挡测试 |
| 失败状态下的专家纠正 | 纠偏、重新抓取、恢复 | 干预率和恢复成功率 |
| 接触阶段的力／触觉数据 | 接触判断、精细控制 | 模型确实使用该模态，且控制接口支持 |
| 人形根部、足接触、负载数据 | 移动操作与全身协调 | 底层控制、目标地面和负载条件 |

这是机制解释和待检验假设。不能保证“加入某类数据一定涨点”。如果控制接口不一致、指令错位或数据分布与工位无关，更多数据也可能使效果变差。

## 5. 公开、仿真、遥操作、商业数据

**公开数据**是别人允许按特定条件获取和使用的资产。优先检查是否有动作、硬件是否相近、标定和时序是否可解释，再考虑规模。许可要按数据、代码、模型分别核查。

**仿真数据**来自虚拟机器人和环境。动作可以由人类遥操作、脚本、规划器或已训练策略生成。已有公开仿真示范可直接用于接入验证；自己生成则需要模拟器、机器人模型、物体资产、传感器与控制配置，以及任务成功判定。当前演示读取 NVIDIA 已发布的仿真数据，没有运行模拟器或新生成仿真示范。

**遥操作**是人通过手柄、主从机械臂、VR、动捕或其他设备控制机器人，系统同时记录感知、状态和控制命令。人用它示范“怎么做”，训练后模型尝试在相似条件下自主产生动作。购买遥操作设备只是第一步，还需要标定、同步、任务复位和数据质检。

**商业获取**可能是购买已有数据、按目标机器人委托采集，或外包标注。采购前先拿样包跑自己的管线，明确动作含义、使用权利、质量扣除与返修标准。

## 6. 不同硬件为什么不能直接共用数据

换 GPU 时，主要调整 batch、精度、分布式和显存策略，数据标签的物理意义通常不变。

换机器人时，需要回答：轴数和关节顺序相同吗？位置还是速度命令？长度是米还是毫米？夹爪 0 表示开还是关？动作是在基座、世界还是工具坐标系下？新机器人控制器能执行相同接口吗？

即使两台设备都输出 14 个数，也可能不能直接混合。本次原型因此把统计和训练探针按来源分开。它验证共享工程流程，没有证明跨本体动作迁移。

机械臂与人形共享视觉、语言、数据管理等技术；人形额外涉及移动基座、双手、接触、平衡与负载。静止桌面拿取数据不能替代带负载行走数据。

## 7. 一个你可以亲自解释的数据错误

真实双臂样本的一行 `language_persistent` 包含多个带时间戳的步骤。0 秒“拿起领带”，后续“卷起领带”“放进收纳盒”等标注也在同一个列表里。

如果把整个列表都作为当前语言条件，训练时模型会提前看到未来阶段信息。现在的处理是保留原始文件，只给当前训练窗口选择时间戳不晚于当前时刻的最近标注。

同样，选“最近的视频帧”可能选到未来帧；原型按源时间选过去帧。但这只证明源时间计算没有越界，设备时钟和传输延迟是否准确仍需要采集系统标定。

这两个案例能说明管线的价值：**它把容易隐藏在文件里的问题变成显式规则和可验证结果。**

## 8. 主管可能追问什么

**现在机器人已经能干活了吗？**

还没有。这次完成的是数据接入和训练工程验证，后续要用具体任务、目标机器人和真实模型验证执行能力。

**为什么先不把数据全下载下来？**

目前先建立资产索引，再用代表样本验证是否能读、如何对齐、是否支持目标训练。验证后扩容能减少存储浪费和重复适配，也更容易判断应该补哪类数据。

**管线以后能自动处理所有新数据吗？**

相同契约的新批次可以复用；首次遇到新格式、新机器人或新动作接口仍需要 reader 和语义适配。缺失的控制器、标定和动作标签无法靠重命名自动补齐。

**为什么没有直接微调最大模型？**

这次先检验数据与训练之间的工程接口，降低 GPU 试错成本。下一阶段应选一个有明确接口与计算预算的上游 VLA，再跑官方加载器和微调流程。

**loss 下降能说明什么？**

说明这个小模型可以在当前训练样本上拟合动作标签，且工程链路可反向传播。它不能说明机器人执行成功，也不能证明泛化或公开数据带来的收益。

**为什么还需要现场部门参与？**

现场知道什么问题有价值、失败代价是什么、动作合格标准与节拍是多少。实验室负责模型与数据方案，主管负责资源和优先级，业务与现场共同确定验收条件。

**最后到底建议买机械臂还是人形？**

当前不做最终采购判断。建议先对候选任务的工作空间、移动需求、双手协作、精度、负载和环境改造成本做比较，然后用样包和控制接口验证采购风险。

**我们实验室积累的价值是什么？**

逐步积累对任务、数据、控制接口和失败模式的可验证认识，以及可复用的采集、接入、训练和评测流程。后续每次补采和模型升级都能沿用这些记录来比较结果。
